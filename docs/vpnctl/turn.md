# TURN over TLS

Экспериментальный outbound `turn` открывает UDP-аллокацию на TURN-сервере оператора. Соединение клиент → реле идёт по TCP с проверкой TLS. Реле → узел назначения использует UDP. Для TCP, ICMP и сквозного шифрования IP-трафика можно поместить поверх реле штатный WireGuard endpoint. В клиенте работает один sing-box. [RFC 8656](https://www.rfc-editor.org/rfc/rfc8656.html)

## Сборка и отключение

```sh
tags=$(sed -n 's/^  DEFAULT_TAGS: "\(.*\)"/\1/p' .github/workflows/release.yml)
CGO_ENABLED=0 go build -trimpath -tags "$tags,with_turn" \
  -ldflags '-s -w -checklinkname=0' -o sing-box ./cmd/sing-box
./sing-box version
./sing-box check -c config.json
```

Для обеих Android AAR используется `go run -tags with_turn ./cmd/internal/build_libbox -target android` с обычным окружением мобильной сборки. Штатный релиз обходится без тега. Для отката верните прежний проверенный конфиг, перезапустите ядро со штатной сборкой и проверьте фактический путь трафика. При автоматизации exit status команды `check` проверяет, распознаёт ли конкретный бинарник конфигурацию. Команда `go version -m -json ./sing-box` выдаёт build settings в JSON. Проверка конфига не устанавливает соединение.

Для распространения экспериментальной сборки включите copyright и тексты лицензий поставляемых зависимостей. Pion TURN распространяется по MIT. Состав слинкованных модулей можно получить из конкретного бинарника командой `go version -m`. [Лицензия Pion TURN v5.1.3](https://github.com/pion/turn/blob/f00fda475f1eb3eaa20daac3cd1c0f6a101b9db8/LICENSE)

## Минимальный профиль

```json
{
  "outbounds": [{
    "type": "turn", "tag": "relay",
    "server": "192.0.2.10", "server_port": 5349,
    "username": "vpn-client", "password": "<выданный оператором пароль>",
    "tls": {"enabled": true, "server_name": "turn.example.net"}
  }]
}
```

`server_port` по умолчанию равен 5349. Для частного УЦ укажите его PEM в штатном `tls.certificate_path`. Пустые учётные данные, отключение TLS и `tls.insecure` отвергаются. Храните профиль с правами доступа оператора. Конфигурация содержит пароль в открытом виде.

Адрес реле проходит через dialer sing-box. Для имени задайте обычный `domain_resolver`, доступный до запуска туннеля. Пример с IP и отдельным `server_name` обходится без bootstrap-запроса DNS. Включайте действующие настройки привязки внешнего соединения к uplink в конфигурации шлюза. TURN получает уже разрешённые числовые адреса UDP-получателей. Семейство UDP-аллокации выбирается по адресу первого назначения, для сокета без назначения по умолчанию IPv4. Адрес из другого семейства требует отдельной аллокации. Совместные DNS-правила и `hijack-dns` остаются в маршрутизаторе.

Для WireGuard добавьте `"detour": "relay"` в клиентский endpoint, укажите числовой IP и UDP-порт WireGuard-сервера в `peers` и направьте внутренние маршруты и DNS через тег этого endpoint. Локальный фиксированный `listen_port` у клиента конфликтует с detour. В качестве проверки доступности используйте TCP-пробу через верхний endpoint или ответ на UDP-запрос через реле. Сам carrier поддерживает только UDP. [Сквозной тест](../../include/turn_wireguard_test.go)

## Требования к серверу и восстановление

Нужен доступный с клиента TURN-сервер с TLS-сертификатом на указанное имя, долгосрочной аутентификацией, разрешённым диапазоном UDP-портов аллокации и доступом от реле до нужного узла. Настройте права выданного аккаунта, лимиты и разрешённые назначения на стороне реле. При использовании WireGuard дополнительно нужен обычный WireGuard-сервер. Прикладной трафик после выхода из TURN защищает верхний протокол. Возможность подключения определяется доступностью конкретного реле у провайдера.

Соединение открывается по требованию. На каждый новый пакетный сокет приходится одна аллокация и одно TLS-соединение. Pion обновляет разрешения и аллокацию. Потеря управляющего соединения закрывает сокет и разблокирует ожидающее чтение. Следующее открытие создаёт новую аллокацию. При смене интерфейса ядро сбрасывает активные сокеты. Пакет, потерянный при смене пути, автоматически не повторяется. Истечение срока во время ожидающей записи также может завершить аллокацию.

## Проверка

```sh
go test -race -tags with_turn -ldflags=-checklinkname=0 ./protocol/turn
go test -race -tags with_turn,with_gvisor,with_wireguard -ldflags=-checklinkname=0 \
  -run '^TestWireGuardDetourOverTURN$' ./include
go test -tags with_turn -ldflags=-checklinkname=0 ./protocol/turn \
  -run '^$' -bench BenchmarkRelayedUDP -benchmem
```

На Linux можно проверить системный TUN и утечки в двух изолированных сетевых пространствах имён. Для тестового стенда нужны coturn с TLS, tcpdump, openssl, iproute2, util-linux и доступный `/dev/net/tun`.

```sh
python3 -B scripts/turn_tun_probe.py --sing-box ./sing-box --turnserver /usr/bin/turnserver
```
