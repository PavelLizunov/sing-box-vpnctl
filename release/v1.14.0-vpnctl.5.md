# v1.14.0-vpnctl.5

Security hardening release based on v1.14.0-vpnctl.4.

- Reject negative/excessive CPS numeric lengths and oversized aggregate I1–I5 packet chains before handshake allocation, using the existing protocol packet bound. Reject excessive literal-byte fields before decoding.
- Reject literal CR/LF in AWG string options before normalization, masquerade generation, and UAPI serialization. Preserve existing secret redaction and encoded packet bytes.
- Generate default and custom XHTTP session IDs using crypto/rand; deduplicate custom alphabets before generation and entropy validation. This is hardening, not a claim of demonstrated production session prediction.
- Surface non-200 stream-up upload responses as connection errors. Synchronize download binding and failure, cancel both requests, close bound/late bodies, stop deadline timers, and release XMUX ownership once.
- Pin release actions to upstream-verified commit SHAs. Build the exact resolved tag revision and refuse dispatch revision mismatches. Never overwrite existing published assets or move tags. Generate native GitHub attestations for packaged assets and checksums.

Compatibility: zero-length CPS fields remain accepted; oversized configurations and literal line breaks now fail validation. Duplicate custom session alphabet symbols no longer bias generation or inflate the accepted identifier space. A release workflow rerun for an existing release fails instead of replacing it.

No production deployment or service restart is part of this release task.
